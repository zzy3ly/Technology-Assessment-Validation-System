# 工作流编排对照实验 v1

执行日期：2026-10-13。结果目录：`test_outputs/workflow_ab_v1/`。

## 测试了什么

运行两个目录中真实的 `PlannerAgent.process`，分别在独立 Python 进程中导入；原始结果保存实际导入路径和 Planner 文件 SHA-256。未修改业务代码。

36 条用例来自 12 类场景，每类 3 组数值。任务均为“读取数字→求和→发布 result.json”。执行器实际计算并写入临时文件，评分器读取文件，与数据集中预先计算的期望值比较。计划生成和子 Agent 响应使用确定性替身，未调用真实模型、网络或付费 API。

三组：原版、当前版、当前版关闭节点重试。反思、Skill、checkpoint 均未启用；输入计划和故障规则相同；各组的计划更新均固定为 NO_UPDATE。重试等待设置为零，因此不报告耗时收益。保留新版其他现有编排逻辑，不能将结果解释为单独引入状态转移表的因果收益。

特别的压力假设：最后的报告节点总是声称 COMPLETE，即使缺失上游数据。这用于检验编排器能否阻止上游已失败的流程继续误报。旧版可通过成功重规划恢复的场景，本轮没有覆盖；这会限制结果适用范围。

## 指标定义

- 任务成功：最终真实文件恰好等于 `{"sum": 期望值}`。正确拒绝、异常捕获、及时失败都不算任务成功。
- 声称成功：新版返回状态 succeeded；旧版没有终态字段，按最终回答是否以 COMPLETE 开头判断。正常返回但没有成功声明，不算虚假成功。
- 虚假成功：声称成功且真实文件缺失或内容错误。
- 全任务虚假成功率：虚假成功数 / 全部任务数。
- 成功声明中的错误比例：虚假成功数 / 声称成功数。两个分母不能混用。

## 实测结果

| 指标 | 旧版 | 当前版 | 当前版关闭重试 |
|---|---:|---:|---:|
| 用例数 | 36 | 36 | 36 |
| 真正完成任务 | 3 | 12 | 6 |
| 任务成功率 | 8.33% | 33.33% | 16.67% |
| 虚假成功数 | 27 | 3 | 3 |
| 全任务虚假成功率 | 75.00% | 8.33% | 8.33% |
| 声称成功数 | 30 | 15 | 9 |
| 成功声明中的错误比例 | 90.00% | 20.00% | 33.33% |
| 子节点执行次数 | 102 | 81 | 63 |

当前版相对旧版：任务成功率提高 25.00 个百分点，虚假成功率下降 66.67 个百分点。节点调用减少不能直接称为成本优化，因为其中包含提前终止而未完成的任务。

## 按场景拆分

每格表示“真实成功数 / 虚假成功数”，每类各 3 条。

| 场景 | 旧版 | 当前版 | 关闭重试 |
|---|---:|---:|---:|
| 正常链路 | 3 / 0 | 3 / 0 | 3 / 0 |
| 一次失败后可恢复 | 0 / 3 | 3 / 0 | 0 / 0 |
| 一次超时后可恢复 | 0 / 0 | 3 / 0 | 0 / 0 |
| 持续失败 | 0 / 3 | 0 / 0 | 0 / 0 |
| 持续超时 | 0 / 0 | 0 / 0 | 0 / 0 |
| 空输出但报成功 | 0 / 3 | 0 / 0 | 0 / 0 |
| 提前退出但报成功 | 0 / 3 | 0 / 0 | 0 / 0 |
| 数值错误但报成功 | 0 / 3 | 0 / 3 | 0 / 3 |
| 依赖不存在 | 0 / 3 | 0 / 0 | 0 / 0 |
| 向后依赖 | 0 / 3 | 0 / 0 | 0 / 0 |
| 数字与字符串依赖 ID 混用 | 0 / 3 | 3 / 0 | 3 / 0 |
| 重复节点 ID | 0 / 3 | 0 / 0 | 0 / 0 |

增加的 9 次真实成功：6 次来自有限重试，3 次来自依赖 ID 规范化。拦截失败、空输出和无效计划主要降低虚假成功，并不等于修好了任务。

## 局限与可用于简历的表述

这是一组确定性故障注入开发集，36 个用例不是 36 个独立业务场景，而是 12 类场景的数值变体。不据此计算统计显著性或推断线上流量表现；尚无真实模型端到端 A/B、独立留出集或成功重规划覆盖。

结果证实当前编排在这些条件下能提高恢复能力和失败判定准确性；语义错误的三条仍全部漏检，说明 succeeded 不能证明用户目标已满足。业务验收器仍有必要。

简历可写：**针对 12 类编排异常构建 36 条确定性故障注入用例，对比原版 Planner，任务完成率由 8.3% 提升至 33.3%，全任务虚假成功率由 75.0% 降至 8.3%；通过关闭重试的对照验证恢复机制贡献。** 必须保留“故障注入”限定，不能改为“真实业务成功率”。

## 复现与审计

```powershell
.\.venv\Scripts\python.exe benchmarks/run_workflow_ab.py
.\.venv\Scripts\python.exe -m unittest tests.test_workflow_ab -v
```

`dataset.json` 保存全部计划、故障类别、输入和期望值；`legacy.json`、`current.json`、`current_no_retry.json` 保存每条用例的实际文件内容、返回值、异常、调用轨迹和状态机轨迹；`summary.json` 保存总指标和分场景统计。临时工作文件运行后清理，其内容已记录在原始结果中。
